# Integration task specification template

The instructor completes this file for the cohort’s selected third-party library. Do not connect the task to a production account or use real customer/payment data.

- Third-party library/framework: `[name]`
- Exact version pinned in the project: `[version]`
- Behavior to implement: `[small observable feature]`
- Public input/output/error contract: `[contract]`
- Approved internal component to search for: `[catalogue entry/type]`
- Local verification: `[mock/fake and test command]`
- Files in scope: `[paths]`
- Out of scope: production calls, real credentials, unrelated redesign, duplicate wrapper where an approved component exists.

The baseline and grounded runs must use the same completed specification and start from identical clean copies. The grounded run should search the internal catalogue first and consult official docs for the pinned version before editing.
